# PM 미팅 정리 (2026-09-29)

> PM 1차 미팅 내용을 정리한 문서입니다. 노션 회의록(PM 미팅 > 1차-9월29일화요일)을 옮겼어요.

## PM 총평

- 현재 위험도가 높고, 이대로면 개발을 완성하기 어렵다는 판단이에요.
- 저장소에 문서 말고는 결과물이 없어요.
- 흐름이 안 맞고 각자 따로 노는 느낌이에요.
- **다음 클라이언트 미팅까지는 결과물이 있어야** 해요.

## 역할 분담

- 수혁: 메인 도메인, 백엔드 전반, 발표
- 민서: 백엔드 아키텍처, DB 설계, 수혁의 백엔드 개발 지원
- (발언자): 프론트, UI/UX
- 디자인: 같이 고민하기로 함 (담당자 미정)
- PM 의견: 백엔드가 2명이니 역할이 깔끔하게 나뉘어야 해요.

## 저장소 / 이슈

- 레포가 실수로 private이라 이슈는 등록됐지만 공개가 안 됐어요. public으로 전환 중이에요.
- 프론트 이슈 4개를 등록했어요. 전체 기능은 한꺼번에 올리지 않고 나눠서 올릴 예정이에요.
- PM 요청: **이슈마다 담당자(Assignee)를 지정**하고, **서로 코멘트를 달기**.

## 핵심 논의: 병동 생성 기능

- 기존 기획: 클래스룸처럼 병동(방)을 생성하는 구조
- PM 지적: 수간호사 한 명은 병동 하나만 맡는데, 사용자가 병동을 여러 개 만들 이유가 있나?
- 결론
	- 시스템 내부적으로는 병동이 여러 개(병동별 데이터 분리) → 맞음
	- 사용자 입장의 "병동 생성" 기능 → 필요 없음. 자기 병동에 들어가서 근무표를 작성하는 구조로
- 팀 내 싱크가 안 맞았던 대표적인 사례예요. 이슈 내용도 바뀔 수 있어요.

## 정리된 기능 흐름

1. 간호사 로그인 → 코드를 입력해서 병동에 소속 (팀 참가 방식)
2. 수간호사가 간호사 등록 (근무표를 짜기 전에 필요)
3. 간호사가 오프·연차 신청
4. 수간호사가 신청 내용과 간호사 능력치를 보고 승인 또는 보류
5. 근무표는 자동 생성 후 수정하는 방식
	- AI 대신 알고리즘으로 구현 → "될 것 같다"로 합의

## 화면 구분

- 관리자(수간호사): **PC**. 엑셀 같은 형태의 근무표 편집
- 간호사: **모바일** 위주. 기능은 3개면 충분
	- 오프 신청
	- 연차 신청
	- 전체 근무표 보기

## 디자인

- Figma 링크가 아직 없어요.
- 메인 기능부터 잡는 게 브랜딩에도 도움이 되므로, 엑셀 느낌의 메인 화면부터 만들어요.

## PM이 제시한 진행 방식

- 팀 협업툴에 쓴 내용을 LLM으로 한 번에 정리 → 다 같이 읽고 싱크 맞추기 → 그다음 이슈 등록
- 선생님 미팅 흐름: 프론트 이슈 확인 → 오늘 진행 상황 → 누가 했고 누가 코멘트했는지 → 결과물 확인 → 다음 미팅까지 목표 정하기
