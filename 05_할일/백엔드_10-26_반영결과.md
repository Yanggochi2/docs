# 10/26 클라이언트 회의 — 백엔드 계획 및 반영 결과

작성일: 2026-11-01 (11-02 수정). 출처: 10/26 회의록, 11-02 팀 확인.
이 회의의 기능 범위 변경이 기존 v1.0 인증·신청 명세보다 우선한다.

> **11-02 수정:** 10/26 회의의 "로그인 제거"는 **일반 간호사 로그인만** 없앤다는 뜻이다. 수간호사는 계정으로 로그인해 병동·근무표를 관리하고, 일반 간호사는 확정 근무표 공유 링크로 조회만 한다. 처음 PR #85에서 만든 편집용 비밀 링크(관리 토큰) 진입은 백엔드 PR #86에서 수간호사 로그인으로 바로잡았다.

## 완료한 백엔드 작업

| 작업 | 결과 | 검증 |
|---|---|---|
| 월간·정렬 기본값 | 월 전체 셀, 기본 month/proficiency. 수간호사→차지→일반, 각 그룹 경력 내림차순. 이름순 지원 | 관리 목록·월별/ID 근무표·공유 조회 |
| 간호사 등록/수정 | 계정 없이 등록, 공통 joinedYear 폼 계약. 소속 날짜 유지, 프리셉터를 isPreceptor/preceptorOf로 분리 | 연도 검증, 중복, 수정 버전, 다른 병동 차단 |
| 28명 목데이터 | 수간호사1·차지2·일반25. 일반25년차, 차지23년차, 프리셉터5~6년차 포함 | 재실행해도 인원 중복 없음 |
| 생성기 | 차지 평일 D·주말/공휴일 O, 일반 O=주말∪공휴일+1. E/N 독립 배분 및 편중 감점 | 28명 하드 위반0, E/N 인원별 차이2회 이내 시나리오 |
| 고정 일정 | AL/ED 자동 보존, 종이 달력 O는 관리자가 직접 입력 후 fixedCells로 고정 | 재생성·월 경계·실패 시 기존 셀 보존 |
| 일반 간호사 로그인/온라인 신청 제거 | 일반 간호사 가입·계정 연결·온라인 오프 신청·승인·알림 API 제거 | 제거 경로 404 |
| 수간호사 로그인 유지 | 회원가입·로그인·세션 갱신·로그아웃 (HttpOnly 쿠키 + CSRF 토큰). `/wards/me/*` 관리 API는 수간호사 역할만 허용. 편집용 비밀 링크 제거. 기존 병동의 합성 사용자를 실계정으로 바꾸는 `link-head-account` 운영 명령 | 비로그인 401, 일반 계정의 관리 API 차단 |
| 공유 조회 | 확정본 링크 발급/교체/폐기, 확정 취소 시 폐기. 민감 프로필 제외 | 공유 토큰으로 관리 API 사용 불가, 옛 링크 재사용 불가 |
| 기존 데이터 전환 | 새 테이블/프리셉터 속성 추가, 입사일 원본 유지, 별도 운영자 전환 명령 | 기존 SQLite 전환 및 재실행 |

백엔드 작업 브랜치: `feature/client-1026-backend`. PR #85(10/26 반영) 후 PR #86(수간호사 로그인 복구)으로 main에 병합했다 (`4d35e27`, 11-02). 배포는 별도 단계다.

전체 테스트: PR #86 기준 **85 passed**. 수간호사 로그인 편집, 일반 계정의 관리 API 차단, 비로그인 공유 조회, 공유 토큰의 관리 API 사용 차단 포함.
실제 PostgreSQL 서버 및 운영 데이터로의 전환은 아직 검증하지 않았다.

## 프론트엔드 후속 작업

- 일반 간호사용 가입·계정 연결·신청·승인·알림 UI 제거.
- 수간호사 회원가입·로그인 화면과 인증 가드는 유지. 관리 API는 쿠키 세션 + CSRF 토큰으로 호출.
- 편집 링크(`/manage`, 관리 링크 카드, `management-link` API)는 쓰지 않음.
- 공유 화면 `/shared/[token]`에서 `GET /api/v1/shared/schedules/{token}` 호출. 읽기 전용 화면 제공.
- 간호사 등록·수정 폼 재사용, `joinedAt`→`joinedYear`, 프리셉터 별도 속성.
- 월간 기본 화면, 숙련도/이름 2개 정렬.
- 확정 후 공유 링크 발급·복사·교체·폐기.

프론트엔드 main(`2875dea`)은 계약 확인만 했으며 코드를 수정하지 않았다.
기존 쿠키 인증 흐름은 그대로 쓰되, 제거된 API를 부르는 화면과 공유 링크·간호사 폼 변경은 함께 연동해야 한다.

## 클라이언트에게 확인할 도메인 항목

1. D/E/N 필요 인원이 최소 인원인지 정확한 정원인지: 현재 최소로 적용. 남는 근무는 D 우선.
2. 수간호사도 차지처럼 평일 D로 편성하고 직접간호 인원에 포함하는지: 현재 포함.
3. 차지의 주5일 기준과 추가 O 1일의 관계: 현재 차지는 주말/공휴일만 O.
4. 중도 입·퇴사자의 O 비례 계산과 연차의 별도 집계 기준: 현재 비례·반올림, AL/ED 별도.
5. 설/추석/대체/임시공휴일: 현재 자동 수집이 없으므로 관리자 보정 필요.
6. 공개 표에서 AL/ED 표시 여부: 현재 부재 사유를 드러내지 않도록 O로 통일.

각 항목의 선택지·권장 검토안·검증 방법과 PostgreSQL 전환, 다개월 생성 검증, 운영 발전 과제는 [백엔드 미결정 사항 및 발전 로드맵](백엔드_미결정사항_및_발전로드맵.md)에 정리했다.
