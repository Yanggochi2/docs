# 병동 근무표 서비스 기능명세서

개발과 테스트에 사용하는 제품 기준 문서

| 문서 정보 | 내용 |
| --- | --- |
| 버전 | 1.0 |
| 작성 기준일 | 2026년 10월 6일 |
| 대상 | 제품 기획자, 디자이너, 개발자, QA |
| 문서 상태 | 기준안. 12장의 미확정 항목은 제품 결정 후 확정 |
| 원문 기준 | 기능명세서 v0.2의 요구사항을 재구성하고 누락된 흐름을 보완 |
| 개정 | 2026년 10월 7일 소셜 로그인(OAuth) 추가: AUTH-08, AUTH-09, D-18, D-19 |

이 문서는 병동 소속 관리, 간호사 정보, 근무 규칙, 근무표 작성과 자동 생성, 신청, 알림, 보안 기능을 정의한다. 기능별 입력과 처리 결과뿐 아니라 권한, 상태 변화, 오류 조건, 검수 기준을 함께 명시하여 구현과 테스트의 해석 차이를 줄이는 것이 목적이다.

원문에서 정의가 빠진 기능은 서로 연결된 흐름이 끊기지 않도록 보완했다. 다만 정책 결정이 필요한 값은 임의로 확정하지 않고 12장에 분리했다. 해당 항목이 승인되기 전까지 관련 수치는 설정값으로 구현한다.

## 1 문서 사용 기준

### 1.1 요구사항 해석

| 표현 | 의미 |
| --- | --- |
| 필수 | 출시 범위에 포함하며 수용 기준을 모두 만족해야 한다 |
| 선택 | 사용자가 입력하지 않아도 기능을 완료할 수 있다 |
| P1 | 핵심 운영 흐름에 필요한 1차 출시 기능 |
| P2 | 핵심 흐름 이후 제공할 개선 기능 |
| 결정 필요 | 제품 또는 운영 정책의 승인이 필요하다 |

### 1.2 기본 원칙

- 권한은 계정이 아니라 병동 소속 관계에 부여한다.
- 일반 간호사는 확정된 근무표만 조회할 수 있다.
- 병동 범위 데이터는 서버가 요청자의 소속과 대상 리소스의 소속을 대조한 뒤 반환한다.
- 퇴사한 간호사와 과거 근무표는 물리 삭제하지 않는다.
- 미확정 정책값은 서버 설정으로 분리해 코드 수정 없이 변경할 수 있게 한다.

## 2 서비스 범위와 사용자

### 2.1 서비스 범위

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 인증과 소속 | 계정 생성, 로그인, 병동 개설, 가입, 권한 이관 | 병원 전체 조직도와 인사 시스템 연동 |
| 인력 관리 | 간호사 정보, 배정 역할, 소속 기간, 퇴사 | 급여, 평가, 징계 |
| 근무표 | 월별 작성, 규칙 검증, 자동 생성, 확정, 조회, 엑셀 | 실시간 출퇴근과 급여 정산 |
| 신청 | 연차, 희망 오프, 희망 근무의 신청과 승인 | 법정 휴가 잔여 일수 정산 |
| 운영 | 알림, 감사 로그, 접근 통제 | 광고 운영 정책과 광고 정산 |

### 2.2 사용자 역할

| 역할 | 설명 | 권한 범위 |
| --- | --- | --- |
| HEAD_NURSE | 수간호사 | 병동 설정, 인력 관리, 규칙 관리, 근무표 생성과 확정, 신청 승인, 감사 로그 조회 |
| NURSE | 일반 간호사 | 확정 근무표 조회, 본인 통계 조회, 신청 작성과 취소, 본인 신청 내역 조회 |

### 2.3 권한 매트릭스

| 기능 | 수간호사 | 일반 간호사 |
| --- | --- | --- |
| 병동 개설 | 소속이 없을 때 가능 | 소속이 없을 때 가능 |
| 병동 코드 관리와 가입 승인 | 가능 | 불가 |
| 간호사 정보 관리 | 전체 | 허용된 항목 조회만 |
| 규칙 설정과 근무표 편집 | 가능 | 불가 |
| 근무표 조회 | 초안과 확정본 | 확정본과 보관본 |
| 개인 통계 | 전원 | 본인 |
| 신청 | 작성, 조회, 승인 | 본인 작성, 조회, 취소 |
| 감사 로그와 엑셀 내보내기 | 가능 | 불가 |

일반 간호사 응답에서는 타인의 숙련도, 총 경력, 건강 상태, 신청 사유, 초안 근무표와 감사 로그를 제외한다. 화면에서만 숨기지 않고 서버 응답에서 필드를 제거한다.

## 3 공통 데이터와 상태

### 3.1 간호사 정보

| 필드 | 형식 | 필수 | 수정 | 설명 |
| --- | --- | --- | --- | --- |
| name | 문자열 | 예 | 예 | 이름 |
| role | 열거형 | 예 | 제한 | HEAD_NURSE 또는 NURSE. 권한 이관 기능으로만 변경 |
| dutyRole | 열거형 | 예 | 예 | CHARGE, PRECEPTOR, NEW, GENERAL |
| status | 열거형 | 예 | 예 | ACTIVE, PREGNANT, ON_LEAVE, RETIRED |
| joinedAt | 날짜 | 예 | 예 | 입사일 |
| careerMonths | 정수 | 예 | 예 | 총 경력 개월 수 |
| skillLevel | 1부터 5 | 예 | 예 | 수간호사만 조회 |
| affiliationStart | 날짜 | 예 | 예 | 병동 소속 시작일 |
| affiliationEnd | 날짜 또는 null | 아니요 | 예 | 소속 종료일 |
| preceptorOf | ID 배열 | 아니요 | 예 | 담당 신입 목록 |

position, team, shiftType 필드는 사용하지 않는다. position은 권한 역할인 role과 배정 역할인 dutyRole로 분리한다.

### 3.2 듀티 코드

| 코드 | 명칭 | 편집 규칙 |
| --- | --- | --- |
| D | Day | 직접 입력 가능 |
| E | Evening | 직접 입력 가능 |
| N | Night | 직접 입력 가능 |
| O | Off | 직접 입력 가능 |
| AL | 연차 | 승인된 연차가 자동 입력되며 직접 입력 불가 |
| ED | 교육 | 사용 여부 결정 필요 |
| null | 미배정 | O와 다르며 커버리지 인원에서 제외 |

### 3.3 근무표 상태

| 상태 | 편집 | 일반 간호사 조회 | 진입 조건 | 종료 조건 |
| --- | --- | --- | --- | --- |
| DRAFT | 가능 | 불가 | 빈 표 생성, 생성 완료, 확정 취소 | 자동 생성 실행 또는 확정 |
| GENERATING | 불가 | 불가 | 자동 생성 시작 | 완료, 중단, 실패 |
| CONFIRMED | 불가 | 가능 | 하드 위반 없이 확정 | 확정 취소 또는 다음 달 확정 |
| ARCHIVED | 불가 | 가능 | 다음 달 근무표 확정 | 종료 상태 |

### 3.4 신청 정보

| 필드 | 값 또는 규칙 |
| --- | --- |
| type | ANNUAL_LEAVE, PREFERRED_OFF, PREFERRED_SHIFT |
| status | PENDING, APPROVED, REJECTED, CANCELLED |
| targetDates | 한 개 이상의 대상 날짜 |
| reasonCode | 정의된 코드값. 자유 입력은 ETC일 때만 허용하는 안을 권장 |
| 처리 정보 | 처리자, 처리일, 반려 사유 |

## 4 인증과 병동 소속 기능

### AUTH-01 회원가입

| 항목 | 내용 |
| --- | --- |
| 목적 | 소속이 없는 계정을 생성한다. |
| 사용자 | 비로그인 사용자 |
| 선행 조건 | 동일 이메일 계정이 없어야 한다. |
| 입력 | 이름, 이메일, 비밀번호, 약관 동의 |
| 처리 | 이메일 중복과 비밀번호 규칙을 확인하고 비밀번호를 해시하여 계정을 생성한다. role과 wardId는 입력받지 않는다. |
| 출력 | 계정 생성 후 병동 코드 입력 또는 병동 개설 선택 화면 |
| 예외 | 이메일 중복, 비밀번호 규칙 미달, 약관 미동의 |
| 수용 기준 | 요청에 role 또는 wardId가 포함되어도 서버가 무시하며 계정은 소속 없음 상태로 생성된다. |
| 우선순위 | P1 |

### AUTH-02 로그인과 세션 종료

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자를 인증하고 세션을 안전하게 종료한다. |
| 사용자 | 등록 사용자 |
| 선행 조건 | 활성 계정 |
| 입력 | 이메일과 비밀번호 또는 승인된 소셜 인증 결과 |
| 처리 | 로그인 시 액세스 토큰과 리프레시 토큰을 HttpOnly, Secure, SameSite 쿠키로 발급한다. 로그아웃 시 토큰을 무효화하고 감사 로그를 남긴다. |
| 출력 | 인증된 세션 또는 로그인 화면 |
| 예외 | 인증 실패, 만료된 세션, 비활성 계정 |
| 수용 기준 | 토큰을 본문이나 쿼리스트링으로 전달하지 않는다. 만료된 요청은 401을 반환한다. |
| 우선순위 | P1 |

### AUTH-03 병동 개설

| 항목 | 내용 |
| --- | --- |
| 목적 | 소속 없는 사용자가 병동을 만들고 최초 수간호사가 된다. |
| 사용자 | 소속 없는 로그인 사용자 |
| 선행 조건 | 사용자가 현재 어느 병동에도 소속되지 않아야 한다. |
| 입력 | 병원명, 병동명, D E N 필요 인원, 규칙 프리셋 |
| 처리 | 병동과 소속 관계를 생성하고 개설자를 HEAD_NURSE로 지정한다. 가입 코드를 발급하고 감사 로그를 남긴다. |
| 출력 | 병동 정보와 활성 가입 코드 |
| 예외 | 이미 소속된 사용자, 중복 병동 식별자, 잘못된 필요 인원 |
| 수용 기준 | 병동 생성, 수간호사 지정, 코드 발급이 하나의 트랜잭션으로 완료된다. |
| 우선순위 | P1 |

### AUTH-04 병동 가입 신청

| 항목 | 내용 |
| --- | --- |
| 목적 | 가입 코드로 병동 소속을 신청한다. |
| 사용자 | 소속 없는 로그인 사용자 |
| 선행 조건 | 활성 가입 코드가 있어야 한다. |
| 입력 | 영문과 숫자로 구성된 6자부터 8자의 코드 |
| 처리 | 코드의 활성 상태를 확인하고 중복 신청을 차단한 뒤 승인 대기 신청을 만든다. |
| 출력 | 승인 대기 화면 |
| 예외 | 존재하지 않거나 비활성인 코드, 이미 신청 또는 소속된 사용자, 시도 횟수 초과 |
| 수용 기준 | 유효한 코드는 병동명만 확인시킨 뒤 PENDING 신청을 만들고 수간호사 목록에 나타난다. |
| 우선순위 | P1 |

### AUTH-05 병동 코드 관리

| 항목 | 내용 |
| --- | --- |
| 목적 | 병동 가입 코드를 발급하거나 교체한다. |
| 사용자 | 수간호사 |
| 선행 조건 | 요청자와 병동의 소속이 일치해야 한다. |
| 입력 | 신규 발급 또는 재발급 요청 |
| 처리 | 영문과 숫자로 된 코드를 생성한다. 재발급 시 기존 코드를 즉시 비활성화하고 감사 로그를 남긴다. |
| 출력 | 새 코드와 복사 기능 |
| 예외 | 권한 없음, 코드 생성 충돌 |
| 수용 기준 | 재발급 이후 기존 코드는 가입에 사용할 수 없고 기존 소속에는 영향이 없다. |
| 우선순위 | P1 |

### AUTH-06 가입 승인과 반려

| 항목 | 내용 |
| --- | --- |
| 목적 | 가입 신청을 검토하여 일반 간호사 소속을 만든다. |
| 사용자 | 수간호사 |
| 선행 조건 | PENDING 가입 신청 |
| 입력 | 신청 ID, 승인 또는 반려, 반려 사유 |
| 처리 | 승인 시 role을 NURSE로 고정해 소속을 생성한다. 반려 시 신청 상태를 REJECTED로 바꾸고 감사 로그를 남긴다. |
| 출력 | 처리 결과와 신청자 알림 |
| 예외 | 이미 처리된 신청, 다른 병동 신청, 대상 계정 비활성 |
| 수용 기준 | 승인 요청에 다른 역할이 포함되어도 NURSE만 부여된다. |
| 우선순위 | P1 |

### AUTH-07 수간호사 권한 이관

| 항목 | 내용 |
| --- | --- |
| 목적 | 병동의 관리 권한이 끊기지 않도록 수간호사를 추가하거나 교체한다. |
| 사용자 | 수간호사 |
| 선행 조건 | 대상 사용자가 같은 병동의 활성 간호사여야 한다. |
| 입력 | 대상 간호사, 추가 부여 또는 이관 |
| 처리 | 대상의 role을 HEAD_NURSE로 변경한다. 이관이면 기존 수간호사를 NURSE로 변경한다. 전체 변경을 한 트랜잭션으로 처리한다. |
| 출력 | 변경된 역할 정보 |
| 예외 | 대상 불일치, 마지막 수간호사의 단독 강등 또는 퇴사 |
| 수용 기준 | 작업 후 병동에 최소 한 명의 HEAD_NURSE가 남고 감사 로그에 변경 전후가 기록된다. |
| 우선순위 | P1 |

### AUTH-08 소셜 로그인과 소셜 가입

| 항목 | 내용 |
| --- | --- |
| 목적 | 비밀번호 없이 외부 계정(OAuth 2.0)으로 로그인하거나 가입한다. |
| 사용자 | 비로그인 사용자 |
| 선행 조건 | 서버에 등록된 소셜 로그인 제공자. 제공자 목록은 D-03에 따른다. |
| 입력 | 제공자 선택, 제공자 인증 화면에서의 동의. 처음 가입하는 경우 이름과 약관 동의 |
| 처리 | 서버가 Authorization Code 방식과 PKCE로 제공자 인증을 시작하고, 콜백에서 state를 검증한 뒤 인가 코드를 토큰으로 교환해 제공자 사용자 식별자를 얻는다. 연결된 계정이 있으면 AUTH-02와 같은 인증 쿠키를 발급한다. 연결된 계정이 없으면 가입 화면으로 이동시키고, 이름과 약관 동의를 받은 뒤 소속 없는 계정을 생성하고 소셜 계정을 연결한다. role과 wardId는 입력받지 않는다. 제공자의 액세스 토큰은 사용자 식별 후 폐기하고 저장하지 않는다. |
| 출력 | 인증된 세션. 신규 가입이면 AUTH-01과 같이 병동 코드 입력 또는 병동 개설 선택 화면 |
| 예외 | 사용자가 제공자 동의를 취소함, state 불일치 또는 만료, 제공자 오류, 비활성 계정, 제공자 이메일이 기존 이메일 계정과 같음(D-18) |
| 수용 기준 | 토큰과 인가 코드를 프론트엔드 본문, 쿼리스트링 또는 브라우저 저장소로 전달하지 않는다. state가 없거나 다르면 로그인하지 않는다. 로그인 후 이동 경로는 서비스 내부 경로만 허용한다. 소셜 로그인과 가입은 감사 로그에 남는다. |
| 우선순위 | P1 |

## 13 출시 수용 기준

- 소속 없는 사용자가 회원가입 후 병동을 개설하거나 코드로 가입 신청할 수 있다.
- 사용자가 소셜 계정으로 가입하고 로그인할 수 있으며, 이 과정에서 토큰이 브라우저 스크립트에 노출되지 않는다.
- 수간호사가 간호사와 규칙을 설정하고 월 근무표를 생성할 수 있다.
- 셀 편집, 일괄 편집, 자동 생성 결과에 커버리지와 규칙 위반이 일관되게 갱신된다.
- 하드 위반이 있는 근무표는 확정할 수 없고 확정된 근무표만 일반 간호사에게 공개된다.
- 연차와 희망 신청의 승인 결과가 근무표 검증과 자동 생성에 반영된다.
- 다른 병동의 식별자를 사용한 요청은 데이터를 반환하지 않는다.
- 퇴사자와 과거 근무표, 신청, 감사 로그가 상태 기반으로 보존된다.
- 모든 P1 기능은 정상, 권한 오류, 입력 오류, 상태 충돌 시나리오를 통과한다.
