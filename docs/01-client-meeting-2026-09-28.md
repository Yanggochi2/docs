# 클라이언트 미팅 정리 (2026-09-28)

> 클라이언트 1차 미팅 내용을 정리한 문서입니다. 음성 인식 원문을 문맥에 맞게 보정했습니다.

*음성 인식 오류가 많아서 문맥으로 보정했어요. (예: 수산어사/수관우사 → 수간호사, 큐티/뷰티 → 듀티, 기후스택 → 기술스택, 염차/열차 → 연차)*

## 핵심 방향

- **주 사용자는 수간호사**이고, 듀티를 짜는 사람의 편의성이 최우선이에요.
- 사용자 연령대가 50대 이상이라 **큰 화면과 큰 글씨**가 필요해요. 23인치 모니터 기준으로 봐야 해요.
- 서비스만의 독특한 조작보다는 **보편적인 UI와 동작**을 원해요.
- UI는 기존에 쓰던 **엑셀 형태와 비슷하게** 만들어요. 똑같은 엑셀일 필요는 없어요.
- 메인 컬러는 **버건디 + 화이트**예요.

## 비즈니스

- 무료로 제공하고 **광고로 수익**을 내요. 사용자를 많이 모으는 게 관건이에요.
- 기술스택은 클라이언트 쪽 요구가 없어서 팀이 자율로 정해요.
- 기간은 **약 7주**예요.

## 핵심 기능

- 간호사 관리, 근무 조건 관리, 근무표 자동 생성, 근무표 관리가 기본이에요.
- **인원 변동(추가·삭제)이 잦아서 우선 구현**해야 해요. 인원을 빼거나 넣으면 표가 바로 반영돼야 해요(10명 → 9명).
- 가입 방식:
	- 회원가입 후 **병원(병동)별 코드를 입력하면 해당 그룹에 소속**돼요.
	- "로그인 연결 기능"을 언급했는데, 소셜 로그인으로 추정돼요.
- 권한:
	- 수정과 중요 정보 열람은 **수간호사만** 할 수 있어요.
	- 일반 간호사는 근무 신청과 필요한 스케줄 조회만 해요.
- 근무 데이터는 **누적 기록을 보관**해요.

## 근무 규칙 (확인된 것)

- 근무 유형은 3교대 기준으로 **Day, Evening, Night, Off** 4가지예요.
- 나이트 2회 후에는 반드시 1일 휴식해요.
- 연속 근무와 휴식 규칙이 있어요.
- 임신한 간호사는 나이트에서 제외해야 해요.
- 공휴일(빨간날) 처리가 필요해요.
- 개인 연차 신청을 반영해요.
- 인력 구성 제약이 있어요. 예를 들어 신입이 나이트에 혼자 들어가면 안 돼요.
- 연차에 따라 **숙련도(능력치)를 부여**해요. 이 값은 수간호사만 볼 수 있게 해요.

## 보안 / 개인정보

- 주민등록번호는 수집하지 않아요.
- **환자 정보는 스코프에서 완전히 제외**해요.
- 로그인 정보는 암호화하고 JWT를 검토해요.
- 클라이언트가 내부자 유출 사례(SKT)를 언급했어요. 그래서 권한 분리가 중요해요.

## 다음 주까지

- 디자인 완성이 필요해요.
- **엑셀 형태의 근무표 화면**과 인원 증감 시 동적으로 반영되는 모습을 보여줘야 해요.

## 추가 확인이 필요한 것

- 실제 근무표 예시 데이터를 요청해야 해요. 지금은 표본이 없는 상태예요.
- 금기 근무 패턴(예: 나이트 → 데이 직행 금지 등)의 전체 목록이 필요해요.
- 일반 간호사가 실제로 서비스를 사용할지 불확실해요. 클라이언트도 "활성화될지 모르겠다"고 했어요.
- 마지막에 나온 **결근·긴급 대체 인력 호출** 이야기는 기능 요구인지 불분명해요.
